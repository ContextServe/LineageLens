## Introduction
Integrating SCIP (Sourcegraph Code Intelligence Protocol) or LSIF (Language Server Index Format) with LineageLens allows you to decouple symbol extraction & compiler resolution from the core LineageLens code graph & MCP engine.

Instead of writing and maintaining dedicated compiler bridges for Java (Eclipse JDT), TypeScript (ts.createProgram), or future languages (C#, Go, Rust), LineageLens can ingest standard index.scip files generated by official community indexers.

1. What is SCIP and Why Fits LineageLens
SCIP is a Protocol Buffers standard built specifically for multi-language code intelligence. SCIP indexers (scip-java, scip-typescript, scip-python, scip-go, scip-clang, scip-rust, scip-dotnet) compile/index source code and emit a single index.scip binary.

A SCIP index contains:

* Documents & Symbols: Full AST symbol URIs (e.g., scip-java maven com.example/MyClass#getUser().).
* Occurrences & Roles: Exact ranges (line/col) marked as Definition, Reference, ReadAccess, WriteAccess, or Implementation.
* Relationships: Interface implementations, base class inheritance, and type definitions.

LineageLens can treat SCIP as a Universal Compiler Ingestion Format.

2. The Hybrid Architecture in LineageLens
The hybrid architecture combines Tree-sitter (for zero-dependency syntactic parsing) with SCIP (for compiler-grade semantic resolution) into a 2-stage pipeline:

``` mermaid
flowchart TD
    subgraph Source Code
        SRC[Polyglot Repo: Java, Python, TS, Go, Rust]
    end
    subgraph "Stage 1: Tree-sitter Fast Ingestion (Base Tier)"
        SRC --> TS[Tree-sitter Analyzer]
        TS --> TS_GRAPH[Base CodeGraph<br/>• All Symbols & Files<br/>• Syntax-derived Relations<br/>• Evidence: static_ast & heuristic]
    end
    subgraph "Stage 2: SCIP Compiler Enrichment (Optional High-Precision Tier)"
        SRC -- "scip-java / scip-go / etc." --> SCIP_FILE[index.scip protobuf]
        SCIP_FILE --> SCIP_INGEST[LineageLens SCIP Ingestor]
    end
    TS_GRAPH --> MERGER[Graph Merger Engine]
    SCIP_INGEST --> MERGER
    MERGER --> FINAL[Final .lineagelens/graph.json<br/>• Upgrades resolution to deterministic_fact<br/>• Resolves inter-file interface impls & overloads]
```
## How the 2 Stages Work Together:

### Stage 1 (Always Runs — Tree-sitter):

* Instant offline analysis without compiling or building.
* Extracts every symbol, module container, docstring, and local call site across all languages.
* Edge evidence is tagged: tier: "deterministic_fact", label: "static_ast" (for syntax) or tier: "deterministic_heuristic" (for unresolved cross-file call targets).

### Stage 2 (Opt-in / High-Precision — SCIP Ingestion):

If `index.scip` is present in the workspace root (or generated via lineagelens analyze --scip), LineageLens parses the protobuf file.
SCIP Definition occurrences match against Tree-sitter Symbol IDs by file + line/col range.
SCIP Reference occurrences upgrade unresolved Relation targets to exact compiler-resolved targets, updating the evidence to tier: "deterministic_fact", label: "scip_compiler".

3. Step-by-Step Implementation for LineageLens
Here is how SCIP ingestion can be implemented natively inside LineageLens (src/lineagelens/resolve_scip.py).

**Step A: Read SCIP Index Protobuf in Python**
Install scip-python or the official Protobuf bindings (pip install protobuf scip):

```python
# src/lineagelens/resolve_scip.py
from pathlib import Path
from lineagelens.model import CodeGraph, Evidence, Relation
def ingest_scip_index(scip_path: Path, graph: CodeGraph) -> None:
    """Read an index.scip protobuf file and enrich an existing CodeGraph."""
    import scip_pb2  # Generated SCIP protobuf bindings
    
    index = scip_pb2.Index()
    with open(scip_path, "rb") as f:
        index.ParseFromString(f.read())
        
    symbol_location_map = {}  # symbol_string -> (file, line)
    
    # 1. Map all SCIP symbol definitions to LineageLens symbols
    for document in index.documents:
        file_path = document.relative_path
        for occurrence in document.occurrences:
            # Check if this occurrence is a Symbol Definition (role bit 1)
            if occurrence.symbol_roles & scip_pb2.SymbolRole.Definition:
                symbol_id = occurrence.symbol
                line = occurrence.range[0]  # 0-indexed line number
                symbol_location_map[symbol_id] = (file_path, line)
    # 2. Extract Compiler-verified Relations from SCIP References
    for document in index.documents:
        source_file = document.relative_path
        for occurrence in document.occurrences:
            # If this is a call site / reference to a defined symbol
            if not (occurrence.symbol_roles & scip_pb2.SymbolRole.Definition):
                target_scip_symbol = occurrence.symbol
                if target_scip_symbol in symbol_location_map:
                    target_file, target_line = symbol_location_map[target_scip_symbol]
                    
                    # Find enclosing LineageLens symbol for source_file at occurrence.range[0]
                    source_symbol_id = graph.find_enclosing_symbol(source_file, occurrence.range[0])
                    target_symbol_id = graph.find_symbol_by_location(target_file, target_line)
                    
                    if source_symbol_id and target_symbol_id:
                        # Upgrade or add deterministic relation
                        graph.add_relation(Relation(
                            source=source_symbol_id,
                            target=target_symbol_id,
                            kind="CALLS",
                            file=source_file,
                            line=occurrence.range[0],
                            evidence=Evidence(tier="deterministic_fact", label="scip_compiler"),
                            resolution="resolved",
                            resolution_evidence=Evidence(tier="deterministic_fact", label="scip_symbol_reference")
                        ))
```
**Step B: Graph Merging & Evidence Reconciliation**
Tree-sitter and SCIP generate symbols and relations independently. Step B harmonizes them into a single coherent .lineagelens/graph.json:

1. Symbol ID Alignment:
    * Tree-sitter creates symbol IDs like src/app/utils.py::fetch_data.
    * SCIP creates symbol URIs like scip-python python package 1.0 app/utils.py/fetch_data().
   * Reconciliation: Map symbols using their exact (file_path, start_line, start_column) span.
1. Deduplicating & Upgrading Relations:
   * If Tree-sitter found a relation A -> B marked deterministic_heuristic (e.g., matching call target by function name), and SCIP verifies that A explicitly calls B, upgrade the existing relation's evidence tier to deterministic_fact with label scip_compiler.
   * If SCIP discovers relationships Tree-sitter missed (e.g., dynamic interface dispatch or superclass method inheritance), append the new relation.
```python
# src/lineagelens/merge_scip.py
def merge_scip_into_graph(tree_sitter_graph: CodeGraph, scip_graph: CodeGraph) -> CodeGraph:
    """Merge SCIP facts into the base Tree-sitter graph."""
    existing_relations = {
        (r.source, r.target, r.line): r for r in tree_sitter_graph.relations
    }
    for scip_rel in scip_graph.relations:
        key = (scip_rel.source, scip_rel.target, scip_rel.line)
        if key in existing_relations:
            # Upgrade evidence on existing relation from heuristic to fact
            existing_rel = existing_relations[key]
            existing_rel.evidence = scip_rel.evidence
            existing_rel.resolution = "resolved"
            existing_rel.resolution_evidence = scip_rel.resolution_evidence
        else:
            # Add compiler-only relation discovered by SCIP
            tree_sitter_graph.add_relation(scip_rel)
            
    return tree_sitter_graph
```
**Step C: CLI Auto-Discovery & Indexer Execution**
Users shouldn't have to manually run scip-java or scip-typescript before running lineagelens analyze.

In lineagelens.yaml, allow users to configure auto-indexing (or auto-detect installed SCIP indexers):

```yaml
# lineagelens.yaml
analysis:
  scip:
    enabled: auto  # auto, true, false
    indexer_cmd: "scip-java index"  # Optional override
```

Inside `src/lineagelens/analyzer.py`:

```python
# Check if an index.scip already exists, or auto-run indexer if tool exists on PATH
scip_file = project_root / "index.scip"
if not scip_file.exists() and shutil.which("scip-java") and has_java_files(project_root):
    logger.info("Detected Java files and scip-java on PATH. Generating SCIP index...")
    subprocess.run(["scip-java", "index"], cwd=project_root, check=True)
if scip_file.exists():
    logger.info("Ingesting index.scip for compiler-grade type resolution...")
    scip_graph = ingest_scip_index(scip_file)
    graph = merge_scip_into_graph(graph, scip_graph)
```
**Step D: Re-running Reachability & Resiliency Analysis**
Once the graph relations are enriched with SCIP's compiler-proven targets, re-run LineageLens's existing downstream engines:

1. Dead Code Reachability (reachability.py): Recalculate dead code verdicts. Compiler-resolved calls from SCIP may rescue functions that static heuristic name-matching couldn't prove were live.
2. Resiliency & Risk Analysis (entrypoints.py & analyzer.py): Re-evaluate blast-radius (impact_analysis) and risk signals (like database writes or blocking I/O calls) through the newly verified transitive call chains.

4. Comparison of Architectures for LineageLens
Current Path (Dedicated Compiler per Language)
```
  Repo -> [JDT Bridge (Java)] ----> Custom JSON -> LineageLens Graph
       -> [TS API Bridge (JS)] ---> Custom JSON -> LineageLens Graph
       -> [Jedi / AST (Python)] --> Custom JSON -> LineageLens Graph
  (High maintenance, requires heavy local SDKs per language)
```
Proposed Hybrid Path (Tree-sitter + SCIP)
```
  Repo -> [Tree-sitter Engine] ---> Fast Universal Base Graph (All 50+ languages)
       -> [SCIP Ingestor] -------> Overwrites/Enriches with Compiler-verified Facts
  (Low maintenance, 0-dependency default, compiler-level precision when needed)
```

## Key Takeaways for LineageLens
Tree-sitter gives LineageLens instant, zero-dependency coverage for 50+ languages on day one.
SCIP Ingestion replaces the need to build custom compiler bridges (java_bridge.py, js_bridge.py) for every new language.
Your existing Evidence model (deterministic_fact, deterministic_heuristic, probabilistic) natively supports this hybrid approach—Tree-sitter populates the heuristic/ast tier, and SCIP seamlessly upgrades relations to scip_compiler facts when available.
