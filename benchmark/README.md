# LineageLens Benchmark Suite

A simple, auditable benchmarking tool to evaluate LineageLens MCP (MCP tools) vs. baseline (code exploration) approaches.

## Overview

This benchmark suite compares two scenarios for analyzing code changes:

1. **Scenario MCP**: Claude with LineageLens MCP tools (structured code graph queries)
2. **Scenario Baseline**: Claude with raw file exploration tools (grep, find, read)

Both scenarios analyze the same PR against the real codebase to measure:
- **Token usage** (input, output, total cost)
- **Analysis quality** (accuracy of identified files/symbols)
- **Efficiency** (cost per unit of accuracy)

## Quick Start

### 1. Configure the benchmark

Copy and edit `benchmark.yaml`:

```bash
cp benchmark.yaml my_benchmark.yaml
```

Edit the config:

```yaml
repo:
  url: https://github.com/langchain-ai/langchain
  pr: 39809
  base_commit: ""      # auto-detected from PR
  expected_commit: ""  # auto-detected from PR

language: python       # python | java | js

work_dir: /tmp/ll-bench
mcp_dir: mcptest
nonmcp_dir: nonmcp_test

source_roots: []       # IMPORTANT for non-src/-layout repos:
                       # For langchain, use: ["libs/langchain/langchain"]

model: claude-sonnet-4-5
budget_usd: 3.00
timeout_seconds: 900
mcp_tool_prefix: mcp__lineagelens
```

### 2. Run the benchmark

```bash
python benchmark/run_benchmark.py --config my_benchmark.yaml
```

This will:

1. **Prepare phase**: Clone the repo twice at the PR's base commit, run `lineagelens analyze` on one
2. **Claude phase**: Run Claude on both clones, capturing token usage and analysis
3. **Score phase**: Extract file changes from both plans, compute precision/recall
4. **Report phase**: Generate `report.md` with side-by-side comparison

## Key Features

### Zero Mock - Everything is Real

- **Real PR metadata**: Fetched from GitHub API via `gh pr view`
- **Real clones**: Full git checkout at the exact base commit
- **Real code graph**: Generated by `lineagelens analyze` (Python/Java/JS)
- **Real Claude calls**: Via `claude -p` headless mode with `--output-format json`
- **Real token tracking**: From Claude API response metadata

### Strict Validation

- **Empty graph guard**: If the MCP clone produces <20 symbols, fails loudly with remediation hints
- **Source roots awareness**: Patches `lineagelens.yaml` if your repo isn't in `src/`
- **Tool call verification**: Logs every command before running it
- **Transcript auditing**: Raw `stream-json` output from both scenarios is always persisted to `results/` for complete tool-call traceability (useful for verifying MCP scenario never reads source files)

### Auditable Output

All results stored under `<work_dir>/`:

- `results/summary.md` — Human-readable comparison (cost, tokens, accuracy)
- `results/summary.json` — Machine-readable metrics
- `results/mcp_stream.jsonl` — Raw stream-json transcript from MCP scenario (all tool calls logged)
- `results/baseline_stream.jsonl` — Raw stream-json transcript from baseline scenario
- `mcptest/` — Full MCP clone at PR base commit (input to Scenario A)
- `nonmcp_test/` — Full baseline clone at PR base commit (input to Scenario B)

## Common Issues

### "Graph has only X symbols (expected >20)"

Your `source_roots` config is wrong. LineageLens defaults to `source_roots: ["src"]`, which won't work for repos like langchain that use `libs/langchain/langchain/` instead.

**Fix**: Edit `benchmark.yaml` and set:

```yaml
source_roots: ["libs/langchain/langchain"]
```

Then re-run.

### Clone takes too long

The full langchain clone is ~2GB. Use a smaller test PR first:

```yaml
repo:
  url: https://github.com/some/small-repo
  pr: 123
```

### Java/JavaScript support

Set `language: java` or `language: js` in your config. The benchmark will:

1. Check for JDK 17 + `gradlew` (Java) or Node 18 + `npm` (JS)
2. Pre-build the analyzer (`./gradlew shadowJar` or `npm run build`) before clocking starts
3. Run `lineagelens analyze` the same way (it dispatches to the right analyzer)

## Architecture

### Files

- `run_benchmark.py` — Main script, ~250 lines
- `benchmark.yaml` — Example config (edit this for your test case)
- `prompt.md` — Prompt template (PR title/body + instruction for structured output)

### Pipeline Phases

1. **Load Config** → validate paths, fetch PR metadata from GitHub
2. **Prepare Clones** → git clone + checkout at base commit, run `lineagelens init` + `analyze` on MCP clone
3. **Claude Runners** → call `claude -p` twice with different tool restrictions
4. **Scoring** → extract file lists from plans, compute precision/recall against ground truth
5. **Report** → write summary.md and summary.json

## Advanced: Custom Source Roots

If your repo has a non-standard layout:

```yaml
source_roots:
  - "src"           # Python src layout
  - "lib"           # Ruby-style
  - "libs/foo"      # Monorepo style
```

LineageLens will union these when scanning. Check the lineagelens.yaml it generates with `lineagelens init`.

## Extending the Benchmark

### Adding Symbol-Level Scoring

The prompt template includes a `## Files I would change` section. You can extend this to also extract symbols:

```yaml
## Files I would change
src/file1.py
src/file2.py

## Functions/Classes I would modify
ClassName.method_name
function_name
```

The scorer can then regex-match these and compute symbol-level precision/recall.

### Multiple Runs / Averaging

Run the same benchmark config multiple times (the clones stay in `work_dir` by default, so re-runs reuse them):

```bash
python benchmark/run_benchmark.py --config config.yaml  # run 1
python benchmark/run_benchmark.py --config config.yaml  # run 2
python benchmark/run_benchmark.py --config config.yaml  # run 3
```

Then manually average the results from each `summary.json`.

## Cost & Time Estimates

- **Clone time**: 1-3 min per repo (depends on size; langchain ~2GB = 1-2 min)
- **LineageLens analyze**: 30s - 5min (depends on language/size)
- **Claude MCP call**: 1-2 min (depends on budget_usd and model)
- **Claude Baseline call**: 2-5 min (larger input context)
- **Total**: ~10-20 min per benchmark run (local + API latency)

**Cost**: ~$3-5 per full run on a medium repo (depends on model choice and budget_usd cap)

**Timeouts**: Script defaults to 30 min (1800s) for git clone and analyze operations, adjustable via `timeout_seconds` in config. Raw stream-json transcripts are always persisted to disk for debugging, even if the run times out or partially fails.
